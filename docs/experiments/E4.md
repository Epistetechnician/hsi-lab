# E4 — one reversible adapter update on a frozen base

Packet: `packets/e4-v1.frozen.json`. Base: a hypothesis prior pretrained on fit-split worlds
(add, swap, add+swap). Candidates (trained on tune-split worlds only: copy, add+copy; held-out
uses mix and swap+copy): a rank-2 LoRA adapter (base weights never written; base file read-only,
digest-checked) and an external-memory candidate (signature counts as a retrieval bonus). Eval:
held-out compositional transfer (swap+copy) with 8 support transitions; guardrail: success on
fresh fit-split worlds may not drop more than 2 points.

## Result: NO_CANDIDATE (receipt `E4-receipt.json`)

| Arm | held-out compositional-transfer success |
| --- | --- |
| frozen base | 0.315 |
| LoRA candidate | 0.307 |
| memory candidate (exploratory) | 0.318 |

LoRA − base = −0.007, 95% CI [−0.046, +0.031]: the interval excludes the +0.05 threshold. The fit
guardrail also fails: LoRA 139/200 vs base 158/200 on fresh fit worlds (−9.5 points).

Diagnostic (not part of the receipt): hypothesis-selection accuracy on unseen tune-type worlds rose
from ~0.43 to ~0.61 with the adapter, but fell on fit-type worlds from ~0.96 to ~0.77, i.e. the
adapter learned the new primitive and forgot some of the old prior, and better selection did not
turn into held-out plan success. A candidate that mixes fit-world replay into adapter training is a
new packet, not a retry.

Nonclaims: pure-Python prior, not an LLM; one adapter recipe, one seed.
