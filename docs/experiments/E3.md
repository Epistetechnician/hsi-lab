# E3 — small collective vs one agent at matched exploration

Packet: `packets/e3-v1.frozen.json`. Task family: collective discovery (agent k may only execute
actions {2k, 2k+1}; the other half is discoverable only by the other agent). All arms get 12
exploration calls in total (single: 12 by agent 0; others: 6 per agent). Messages are capped at 24
bytes per task and logged with the Message schema. Decision compares fixed_graph with `single`
and `independent`; `centralized` (raw typed-event log, truncated to the cap) is exploratory.

## Result: PROMOTE (`E3-receipt.json`, independently recomputed)

| Arm | held-out success |
| --- | --- |
| single | 0.305 |
| independent ×2 | 0.420 |
| centralized | 0.623 |
| fixed graph | 0.657 |

fixed_graph − single = +0.352 [0.297, 0.408]; − independent = +0.237 [0.189, 0.286]. Guardrails held
(max 24 of 24 message bytes; compute matched on every task).

Read with care: the advantage is largely structural (each lone agent cannot act on half the
actions), so this shows pooling information across complementary agents works under a byte cap, not
that collectives beat a capable single agent. The compact summary beats the truncated raw log only
slightly (+0.034, not tested for significance). Pilot flagged `underpowered` at max_n=400.

Nonclaims: two scripted agents, one synthetic family, no LLM agents (P1 replication arm not run).
