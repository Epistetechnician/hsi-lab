# E8 (packet e8-v1): does test strength matter when a code model trains on its own verified solutions?

Qwen2.5-1.5B-Instruct 4-bit, local MLX, LoRA, MBPP+ (150 tune tasks, 225 held-out scored under the EvalPlus
tests). Source commit `90b9f97` (clean). Receipt `E8-receipt.json`, digest `033342a807…`, recomputed OK by the
stdlib validator (A2). Design and audit: ADR 0004, `E8-audit.md`.

## Result: NO_CANDIDATE (guardrail breached; primary also inconclusive)
Primary d2_plus − d2_ex: **+0.049, 95% CI [−0.009, 0.107]**, threshold +0.03. Alone this would be INCONCLUSIVE
(interval straddles the threshold and includes 0). The guardrail "d2_plus not below d1_plus beyond 0.02"
failed (0.436 vs 0.484), so the pre-registered rule returns NO_CANDIDATE.

## Reading
- **No evidence that test strength matters here.** The direction is the expected one (more precise filters
  score higher at d1: none 0.404 < base 0.431 < ex 0.458 < plus 0.484, with ex/base swapped), but no
  pre-registered or secondary interval clears zero except the one involving the replicate chain.
- **Chain-to-chain variance swamps the effect.** Two chains with identical filters (plus, plusb) differ by
  0.07 at d2 (0.436 vs 0.507), larger than the primary effect (0.049). One chain per arm cannot resolve it.
  The only "significant" secondary (plusb−ex) is a best-case chain against a single chain and should not be read
  as support.
- **Self-training did not help at all in this setup.** Every chain except plusb d2 scored below the frozen
  base (0.502); unfiltered chains lose ~10–13 points, and the plus chain is below base at d2. With 150
  examples and a fresh adapter per generation this recipe mostly adds drift. The study therefore asks whether
  test strength reduces damage, not whether it produces improvement.
- The synthetic-world finding (E6-noisyver: precision pays) is neither confirmed nor refuted in code.

## Limits
One model, one benchmark (possibly seen in pretraining), one chain per arm except plus, 225 paired tasks
(SE of a paired difference ≈ 0.03). The held-out pool is public and fully used, so the lock fixes order only.
A3 not attempted. Not independent validation (A4).

## What would resolve it
Several independent chains per arm (≥4) so chain variance is estimated, a recipe that does not degrade the
base (more data per generation, lower learning rate, real-data mix), and a larger held-out pool (full MBPP or
HumanEval+). Rough cost: local, ~2 h per chain-set, no GPU spend.
